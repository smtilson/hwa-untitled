# HWA Untitled Project - Agent Instructions

This file provides guidance for AI agents (including Copilot) working on this repository.

## Project Overview

This is a **modular, multi-project repository** for Hubworld: Aidalon (a TCG) related tools and services. The goal is to build five separate but interconnected projects that can be developed simultaneously and potentially spun off into their own repositories.

### The Five Modules

1. **Card Scraper** (`card_scraper/`) - [IN PROGRESS]
   - Scrapes card data from DeckSmith and other sources
   - Outputs standardized CSV/TSV files
   - Foundation for all other modules

2. **Card Query Service** (`card_query/`) - [PLANNED]
   - Provides queryable interface to card data
   - Enables complex filtering and aggregation
   - Outputs JSON via REST/GraphQL APIs

3. **Web App: Shard/Heat Tracker** (`web_app/`) - [PLANNED]
   - JavaScript/React application
   - In-game resource tracking UI
   - Consumer of Card Scraper data

4. **Event Backend** (`event_backend/`) - [PLANNED]
   - Stores and aggregates gameplay events
   - Provides statistics and rankings
   - APIs for other modules

5. **Discord Bot** (`discord_bot/`) - [PLANNED]
   - Async draft management via Discord
   - Integrates with Card Scraper and Event Backend
   - Turn-based picking system

## Key Principles

**Modularity**
- Each module is self-contained with its own dependencies
- Modules communicate via standardized data formats (CSV, JSON, TSV)
- Minimal inter-module coupling
- Independent development and testing

**Documentation**
- [Planning Doc.md](Planning%20Doc.md) is the single source of truth for project status
- Each module has its own README explaining purpose and status
- [DEVELOPER.md](DEVELOPER.md) provides detailed development guidelines

**Data Standards**
- All card data follows the DragnCards CSV format (see Planning Doc.md)
- Columns: databaseID, name, imageUrl, cardBack, type, set, shardCost, barrier, presence, actionLimit
- JSON output uses consistent schema across modules

## Working on a Module

### Setup
```bash
# Activate environment
source .venv/bin/activate

# Install module dependencies
cd module_name
pip install -r requirements.txt
```

### Development
1. **Update Planning Doc.md**:
   - Mark the task as "In Progress"
   - Add brief notes about your approach

2. **Work within module folder**:
   - Keep code isolated in the module directory
   - Write tests (tests/ folder)
   - Use sample data in data/ folder

3. **Follow data standards**:
   - Output card data in CSV/TSV with standard columns
   - Use consistent JSON schema if outputting structured data
   - Document any additions to standard

4. **Update progress**:
   - Mark task as completed when done
   - Update Planning Doc.md with results

### Testing
- Each module should have a `tests/` folder
- Test independently: `cd card_scraper && python -m pytest tests/`
- Don't rely on other modules being complete

## Dependencies & Compatibility

### Module Dependencies
```
Card Scraper (DeckSmith)
  └─ Independent, outputs CSV/TSV

Card Query Service (Internal data)
  └─ Independent, provides query API

Web App
  └─ Independent, no dependencies

Discord Bot
  ├─ Consumes: Some Card data

  └─ Independent, collects events
```

When a module is ready to be its own repository:
1. Ensure it's completely self-contained
2. Create new git repository
3. Update this repo to reference it (submodule or dependency)
4. Update Planning Doc.md with spinoff status
5. Maintain data format compatibility
